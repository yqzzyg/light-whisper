## 长音频转写超时修复（方案 A：自适应等待预算）
- 现象：37 分钟录音重新识别报 `ASR错误: 等待 FunASR 响应超时`，`asr_ms=60011`，随后弹"引擎连接已断开"。
- 根因：`SERVER_RESPONSE_TIMEOUT_SECS=60` 固定预算；整段 `Transcribe` 与流式 `StreamFinish` 会把整段音频一次性解码（`qwen3_native.py::finish` 超窗口就 `concatenate(_chunks)` 后单次 decode），耗时随长度线性增长。本机实测约 19× 实时，37 分钟需 ~117 秒，必然超 60 秒。不是文件体积问题（68MB / 16k 单声道正常）。
- 改动（4 文件）：
  - `audio_service/wav.rs::wav_duration_secs`：只读 RIFF 头推时长（fmt block_align→byte_rate，data 长度按真实字节裁剪），非 WAV/截断返回 None；`audio_service/mod.rs` 导出。
  - `funasr_service.rs`：新增 `long_audio_response_timeout` = `ceil(d*0.1+120)`，下限 120、上限 900 秒；`send_command_to_server_for_audio`（时长 <30s 或未知时回退原 60 秒，实时流式小块不受影响）；`send_command_to_server_inner` 拆出「等锁 deadline + 读取 reply_timeout」两段，音频路径 deadline = reply+5s 保证带时长的具体错误先返回；`TransportFailure::{Disconnected,Timeout}` 让引擎重置的日志与提示区分超时；超时错误追加「音频约 N 分钟，本次等待上限 M 秒」，封顶时再加「可先切分音频再重试」。
  - 调用点：`transcribe_wav_bytes_via_path`（WAV 头算时长）、`transcribe_pcm16` 内联支路（样本数/采样率）、`native_stream.rs::finish`（sample_count/16000）。
- 用真实 68MB/2223.2s 文件核对：预算 343 秒，余量约 2.9 倍。
- 验证：新增单测 5 例（预算曲线/封顶/文案/非超时不动/时长渲染）+ WAV 时长 2 例；`cargo test --lib services::funasr_service` 49 过；全量 lib 918 过 1 失败（`polish_credential_tests` 并行隔离问题，单独跑通过，与本改动无关）；cargo fmt 已应用；`check_formal.py --inventory-only` PASS。
- 未做（留待方案 B）：真正分段解码（`_chunks` 仍累积全部 PCM，1 小时约 230MB）与超时后"只重置会话不销毁模型"（读取被取消会丢失半个 JSON 帧，必须把 stdout 读取搬到独立 task 才能安全保活进程）。
- 自审补丁：①`wav_duration_secs` 原在 data 长度越界（占位 0xFFFFFFFF 且 fmt 在后）时 `checked_add` 返回 None，丢弃已知长度回退 60 秒 → 改为越界即收尾，加占位长度单测；②补 "短音频/未知时长必须回退 60 秒" 回归测试，为此把阈值判断抽成纯函数 `long_audio_budget()`；③`decorate_timeout` 去掉 `filter(|_| message.contains())` 隐式条件，改显式 early return + `is_finite` 防御；④`native_stream` 的 `super::` 内联调用收进 `use super::{...}`；⑤注释"只够 10 分钟"与 19 倍实时不符（60 秒理论上限约 19 分钟），注释+文档一并修正；⑥补注释说明 `owned` 先于 `guard` 析构是承重顺序。
- 已知取舍：`is_timeout_error` 用中文"超时"子串判断（只影响提示与日志，不参与控制流，已在注释标注）；外层 deadline 比读取预算多 5 秒，提示文案以读取预算为准。

## 品牌更名：轻语 Whisper → 会听 / Minutes
- 决策：中文名「会听」，英文名「Minutes」；**不混排**——界面按当前语言显示单一名，安装目录/产物用英文 `Minutes`。
- 分层原则（关键）：品牌字串分散在三个层级，风险差异极大。
  - 展示层（安全）：`src/i18n/zh.ts` `app.title`="会听"、`en.ts`="Minutes" + 各自正文品牌词；`index.html`、`tauri.conf.json` 主窗口 title、README×2、`assets/readme-banner.svg`、`theme.css`/`DESIGN.md` 注释、侧栏 logo `W`→`M`。
  - 安装/数据层：`tauri.conf.json` `productName`="Minutes"（安装目录与 installer 文件名随之变，`scripts/release.sh` 的 INSTALLER 路径已同步）。
  - **未改（有意）**：`tauri.conf.json` identifier 仍是 `com.light-whisper.dev`；`src-tauri/src/utils/paths.rs` 的 `APP_IDENTIFIER="com.light-whisper.app"`（数据目录）未动 → **历史/配置/模型缓存不丢**；`src/lib/constants.ts` 的 10 个 `light-whisper-*` localStorage key 未动；Cargo crate/lib 名、GitHub repo URL、`windows-app-manifest.xml` 的 assemblyIdentity 未动。
- 必须配套的两处（否则功能坏）：
  - 系统窗口标题原来只在 `tauri.conf.json` 静态写死，`main.tsx` 无 setTitle → 任务栏/Alt+Tab 永远旧名。新增 effect：`getCurrentWindow().setTitle(i18n.t("app.title"))` + `i18n.on("languageChanged")` 重设；因 `src/main.motion.test.tsx` 把 `./i18n` mock 成只有 `t`，调用点用 `try/catch` + `on?.()/off?.()` 兜底非 Tauri/测试环境。
  - `capabilities/main.json` 补 `"core:window:allow-set-title"`（`core:window:default` 不含写操作权限，缺了 setTitle 静默失败）。
- 两个隐藏坑：
  - `state/user_profile.rs::default_selection_excluded_apps` 原只排除 `light-whisper.exe`；productName 改后 exe 变 `Minutes.exe`，划词助手会弹在自己窗口上 → 改为 `minutes.exe` + 保留 `light-whisper.exe` 兼容老配置与残留安装。
  - `commands/history.rs` 导出 Markdown 标题写死「轻语 Whisper 转写历史」、导出文件名 `light-whisper-history.*` → 改「会听 转写历史」/`minutes-history.*`。
- 其他 Rust 用户可见文案（托盘 tooltip、启动日志/panic、ChatGPT/Grok 登录提示、LLM 额度错误、默认热词"轻语"）一并替换。
- 验证：tsc / eslint（max-warnings=0）/ vite build / cargo check --all-targets 全过；前端全量 912 测 909 过，3 个 `SettingsPageProviderDiscovery.test.tsx` 超时是并发负载所致，单独复跑 70/70 通过。
