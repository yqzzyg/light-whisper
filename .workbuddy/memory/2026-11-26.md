### 顺手修掉的真 bug：IPC 分段解析一直会失败

`SpeakerSegment` 原来带 `#[serde(rename_all = "camelCase")]`，但 Python 返回的是
`speaker_id` / `start_ms` / `end_ms`，且这三个字段没有 `#[serde(default)]`。
所以 `ServerResponse` 解析分离结果时必然报 missing field，线上表现只是
「分离悄悄不生效、退回整段转写」——非常难查。

修法：`SpeakerSegment` 移到 `history_service` 并**去掉 rename_all**（保持 snake_case
对齐 Python 协议），给前端的 camelCase 展示结构在各命令层单独定义
（`ImportedSpeakerSegment` / `NoteSpeakerSegment`）。加了回归测试
`server_response_parses_python_diarization_segments` 守这条线。

## 崩溃修复：分离撞上 GPU 空闲卸载（access violation）

用户上传 31 分钟音频报错，日志是
`说话人分离失败（… exception: access violation reading 0x…）` + `FunASR 通信中断`。

**根因**：`gpu_idle.GPU_IDLE_ACTIVITY_ACTIONS` 只登记了 `transcribe`，漏了
`transcribe_diarized`。于是分离命令①不持 `_gpu_idle_lock`、②不刷新
`_last_activity_at`。用户开着 180 秒空闲卸载时，分离跑 ~100 秒/小时音频，看门狗
一定在分离中途 `_close_runtime()`；分离结束时第一次 `session.run` 落在已释放的
原生句柄上 → access violation，进程死。卸在属性读取前则是
`'NoneType' object has no attribute 'run'`（同根因的另一种表现）。

**修复**：
- `gpu_idle.py`：`transcribe_diarized` 加进 activity 集合（连带进 LOCKED 集合）。
- `qwen3_asr_server.transcribe_diarized`：逐段识别前再确认 `initialized`/`session`，
  被卸就 `initialize()` 重载。
- `_run_inference`：`session is None` 抛「运行时未加载」，不再退化成语焉不详的 AttributeError。

**教训**：以后任何新增的耗时长命令，必须同时登记进 `gpu_idle` 的两个集合；
漏了不是慢，是崩进程，而且崩在原生层、Python 栈帧拿不到。
计划文档 §6.5 有完整时序。

## 分段粒度：adjacent_merge_gap_seconds 1.0 -> 2.0

用户反馈同一段独白被切成 5 张卡片。查实：`extract_segments` 已把 ≤0.5s
的帧空隙接上，而 106 对同说话人相邻段的间隔全部 >1.0s（最小 1.16s），
所以 1.0 这个合并阈值一次都没触发——是空阈值，不是算法不准。
缝隙能量中位 0.0084 vs 段内 0.0791，确认是真停顿、不是漏标。

改成 2.0 后同一条 1868s 录音：175 段 -> 91 段，中位 5.74s -> 9.94s，
≤3s 段 51 -> 23，截图里 63-108s 的五张卡片合为一张，说话人切换未被吞。

**代价（重要）**：ASR 时间 59.9s -> 138.2s。原因是段变长后的超线性成本：
实测 30s=25 ms/s、60s=63.6 ms/s、110s=161 ms/s。`max_segment_seconds=115`
按「不分块上限」定的，在成本上是纯亏；8 段 >60s 合计 624s，按 161 ms/s
要 100 秒，切成 30s 只要 15.6 秒。下一步应把上限降到 30-45s（尚未做）。

文档：计划文档 §9.7。测试：test_speaker_diarize 加 2 条默认值回归（27 passed）。

## 段长上限 115 -> 45（成本导向，不是模型上限）

承接上一条：把段合并到 2.0s 后 ASR 反而 138s，根因是长段的超线性成本。
把 `max_segment_seconds` 从 115 降到 45 后同一条录音重跑：

| 配置 | 段数 | 中位 | 最长 | ASR | 端到端 |
|---|---|---|---|---|---|
| 1.0/115 | 175 | 5.7s | 57.0s | 59.9s | 107s |
| 2.0/115 | 91 | 9.9s | 112.8s | 138.2s | 200s |
| **2.0/45（采用）** | **106** | **12.0s** | **43.3s** | **73.0s** | **122s** |
| 2.0/30 | 123 | 16.3s | 28.5s | 66.1s | 119s |

30s 只比 45s 快 7 秒却多 17 张卡片，边际收益为零，所以定 45。

另：`split_long_segments` 是按时长平均切，不是找静音点切，所以段越短越容易
把一句话拦腰截断。这是选 45 而不是 30 的第二个理由。真要彻底解决，得改成
在段内找能量最低点切——目前没做。

测试：test_speaker_diarize 28 passed（新增 1 条锁 max_segment_seconds <= 60）。
文档：计划文档 §9.7 已补四档对比表。

## 阈值：不做用户配置，改「唯一真源 + 覆盖入口 + 设备自适应」

用户问「这么多阈值写死，要不要做个配置的地方」。结论是不做用户面板：
这些数没有用户视角的正确值，调错只表现为静默分错人，组合也不可测。

落地三层（文档 §9.8）：

1. `DiarizeOptions` 收拢三处裸数字 —— `extract_segments` 的
   `max_gap_seconds=0.5` 默认参数（直接删掉参数）、`_vote` 的 `>=0.5`、
   `_overlap_flags` 的 `mean()>=0.5`、`_embed_windows` 的 `<2`。
   1.0 合并阈值当年变成空阈值，根因就是这三层各自为政。
2. `LIGHT_WHISPER_DIARIZE_OVERRIDES`（JSON）：未知键/类型错/越界/坏 JSON
   抛 ValueError → 服务端记 ERROR 退回默认；被覆盖的键记 locked，优先于
   自动推导。每个字段有区间，`merge_centroid_cos` 下界取 0.70（异人实测 0.683）。
3. `adapt_options(base, backend, gpu_memory_total_gb, duration_seconds, locked)`：
   段长上限（CUDA+≥8GB→60，否则 45，再叠「60s+3% 时长」预算）、嵌入步长
   （非 CUDA 或 >45min→6，>90min→8）。

**真实运行才发现的 bug**：`Qwen3ASRServer._get_gpu_device_info(self)` 收窄了
基类签名（基类 `(*, include_memory=False)`），自适应一传参就 TypeError，被
`transcribe_diarized` 的 except 吞成「分离失败降级」——界面只表现为这次没做
分离。已修签名 + 补契约测试。测试没抓到是因为桩把整个方法 patch 掉了。

另修 `_get_gpu_device_info` 缓存：不区分「查过显存/只查名字」，`initialize()`
先跑无 memory 版本后，后续要显存的调用恒为 None（自适应静默失效）。

验证：test_speaker_diarize 44 passed（+16）、test_qwen3_asr_server +1 契约测试；
真实 31 分钟音频重跑 45s/步长4 → 106 段、0 段 >45s、文本长度与 tune45 完全一致
（8886 字），确认「收拢阈值 + 自适应」没有改变结果。

## 同一类坑又踩了两次（阈值不在一个地方）

实现「唯一真源」的过程中，真实运行 + 全量测试各抓到一个：

1. `Qwen3ASRServer._get_gpu_device_info(self)` 把基类 `(*, include_memory=False)`
   签名收窄，自适应一传参就 TypeError，被 `transcribe_diarized` 的 except 吞成
   「分离降级」——界面只表现为这次没做分离。已修签名 + 契约测试。
2. `Diarizer.run(options=...)` 只换了 run 的局部变量，`_embed_windows` /
   `_vote` / `_overlap_flags` 仍读 `self.options`，自适应步长静默不生效。
   已改为三个 helper 显式接收 options，并加回归（同一 Diarizer 传 stride 1/4，
   嵌入次数必须 8/3）。
3. 另外 `_get_gpu_device_info` 缓存不能塞 `gpu_memory_total: None`——会让
   `test_failed_probe_does_not_publish_stdout_as_gpu_metadata` 失败（响应体
   凭空多字段）。改用独立属性 `_gpu_memory_probed` 记「查过」。

**教训**：给已有函数加参数时要顺着调用链找所有读实例状态的地方；
「新增参数无人报错但不生效」比抛异常难查得多。

校验：test_speaker_diarize 46 条、test_qwen3_asr_server / test_qwen_gpu_metadata
/ test_gpu_idle 共 81 条通过；真实 31 分钟音频复跑两次，106 段、文本逐字一致。
