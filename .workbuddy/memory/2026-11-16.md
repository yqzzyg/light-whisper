## 去掉 Python 运行时方案与评估（产出 docs/remove-python-runtime-plan.md）
- 用户目标确认：去掉 Python 这一层，让 Rust 直连 audiocpp.dll。（先误当成要直接改代码，已回滚：git checkout 两处 mod 声明 + 删除新建的 services/audiocpp/ 与 funasr_service/qwen_runtime.rs，工作区已恢复干净。）
- 关键事实：Python 从不跑 Qwen 模型。推理在 audio.cpp（C++）里，Python 只是 ctypes 编排层；Python 进程内真跑推理的只有 FireRedVAD（onnxruntime）。
- ABI 事实：build/r2t2/source/include/audiocpp.h 542 行 / ABI 0.5，纯 C、无 C++ 跨界、无异常外泄；Python `_bind()`(r2t2_native.py:96-138) 只绑 21 个符号，离线路径只用 12 个。abi_version 打包 (major<<16)|(minor<<8)|patch；result_text 返回 7(NOT_AVAILABLE) 表示无稳定文本，非错误。
- 三路线：①Rust sidecar 替换 engine.exe（协议层零改动、崩溃隔离保留、25–39 人日）②进程内 FFI（+5–8 人日，失去 CommandProcessGuard 的 crashed→重启隔离）③推荐先①再评估②，②很可能应跳过（收益仅省 IPC，推理耗时才是主项）。
- 工作量分解：Python 运行时 13 文件 4160 行 → 估 3000–4000 行 Rust。最重是阶段 3（R2T2 流式 + QwenPipelineRuntime 双线程预览流水线，8–12 人日）与阶段 4（VAD，6–10 人日）。
- 最大变量：FireRedVAD 的 onnxruntime（2.39MB onnx + kaldi_native_fbank）。优先评估改用 audio.cpp 自带 VAD（task 词表含 "vad"，artifact 有 AUDIOCPP_ARTIFACT_VAD_STATE），可彻底去掉 ONNX 链；退路是 ort crate（+20–40MB）或 tract（算子覆盖风险）。
- 已有资产：Rust 侧 protocol.rs(236) 描述完整逐行 JSON 协议、native_stream.rs(306) 已有客户端流式状态机、funasr_service.rs:1294-1528 已有 HF 缓存就绪判定（下载链只缺下载器本体）。
- 风险：行为一致性（预览回退/提交时机、取消后迟到结果、R2T2 滚动回滚与 coalesced_finish 320ms 尾音、热词拼接）必须做逐字对照回归；GPU 空闲卸载需 native 推理固定专用线程；TLA+ 建模的是应用级状态机非 IPC，路线①不直接破坏模型，路线②需重审"引擎崩溃"状态可达性。
- 收益：安装包去掉 Python 运行时+PyInstaller+onnxruntime+numpy+huggingface-hub+kaldi-native-fbank+soundfile+requests，Python 直接依赖归零；冷启动省几百 ms；推理延迟基本不变。

## build_r2t2_runtime.py 报错根因与应急修复（已验证）
- 报错：`prepare_source` 第 76 行 `RuntimeError: Native source contains changes other than the reviewed R2T2 patch`；用户清空 build/r2t2/source 重跑后仍复现。
- 根因：脚本 `:70-76` 用 `git diff --binary --unified=4 HEAD` 与仓库内 patch 做**字符串全等**比对；`index` 行的 blob 哈希缩写长度由 git 按仓库对象数动态决定（下限 7，`2^(2n)>objects`；门槛 2^14=16384）。本机 source 是 `--filter=blob:none` partial clone，`in-pack 19146` → 8 位；而 patch 的 36 条 index 行全是 7 位。差异仅 36 行 index 元数据，剔除后 diff 与 3499 行 patch 逐字节一致；`--abbrev=7` 时全等成立。
- 为什么"另一台电脑能跑"：`build/` 在 .gitignore:12，源码树不进版本库，每台机器各自 clone，对象数/git 版本/core.abbrev 不同 → 7 位就通过。另 `pnpm tauri dev` 不跑此脚本（dev 允许 0 字节 engine.tar.xz 占位），与"启动"是两条路径。
- 应急（已执行并验证）：`git -C build/r2t2/source config core.abbrev 7`，随后直接调用 `prepare_source(Path('build/r2t2/source'))` 无异常通过。该配置在 build/ 内、不进版本库、零代码改动，但**重新 clone 会丢失**。
- 治本方案（尚未落地，待用户确认）：比对前剔除 `index ` 行做语义比较，需同步改 `scripts/build_r2t2_runtime.py:73/97`、`scripts/build_reuse_runtime.py:28`、`scripts/test_native_source_checkout.py:97`。固定 `--abbrev=7` 只是治标。
- 关联：patch 最近提交 `de40d7f fix(build): correct stale post-image hash in R2T2 native patch index line`，说明此类失配反复出现。

## CUDA 后端 CMake 配置失败：CUDA 12.0 与 MSVC 14.42 硬不兼容
- 现象：`--backend cuda` 时 cmake configure 退出 1，`-- Configuring incomplete`；stderr 被脚本第 238 行 `stdout=PIPE` 吞掉，真实错误需复现命令才能看到。
- 根因：`CUDAToolkit/v12.0/include/crt/host_config.h:151` 硬编码 `#if _MSC_VER < 1910 || _MSC_VER >= 1940 → #error unsupported Microsoft Visual Studio version`。本机唯一 MSVC 工具集 `14.42.34433`（_MSC_VER 1942，>=1940），nvcc 编译 CMakeCUDACompilerId.cu 时抛 C1189，CMake 卡在 CMakeDetermineCompilerId 阶段。
- 版本不匹配：项目 pin CUDA 12.9 + MSVC 14.44 validated（docs/development.md:7,34；build_r2t2_runtime.py:217 提示 validated with CUDA 12.9）；本机只有 CUDA v12.0（CUDA_PATH 环境变量）+ MSVC 14.42。GPU 为 RTX 3050 Ti Laptop / sm_86 / 驱动 581.29。
- 三种绕过**实测全部失败**（EXIT 1）：`CUDAFLAGS=-allow-unsupported-compiler`、`-DCMAKE_CUDA_FLAGS=-allow-unsupported-compiler`、`-DCMAKE_CUDA_COMPILER_FORCED=TRUE`。原因：CMake 编译 compiler-id 探针时不读这些 flag，C1189 在预处理阶段就抛。要强行绕过须手写 CUDA toolchain / 预置 compiler id，风险高（NVIDIA 明确警告可能编译失败或运行错误）。
- 结论/建议：①只是改代码、启动、调试 → 不需要 CUDA，`--backend cpu` 已于 11:50 成功，`src-tauri/resources/r2t2-native/cpu/` 9 个文件 + runtime-manifest.json 哈希全部通过校验，可直接 `pnpm tauri dev`。②要打安装包 → `build_engine.py::validate_r2t2_runtime()` 强制要求 cpu+cuda 两个后端都在，必须装 CUDA 12.9（并建议 MSVC 14.44），或为 CUDA 12.0 加装 14.39 及以下工具集（但项目未在该组合验证）。
- 提醒：用户常把 `--backend cpu` 与 `--backend cuda` 混跑；`-B build/r2t2/cuda` + `-DENGINE_ENABLE_CUDA=ON` 即 cuda 后端，两条命令产物目录与依赖完全不同。

## 严重回归：导入音频后首页录音全部失败（已修复）
- 现象：连续 7 次导入成功（历史 id 4–10）后，首页录音 session 1–4 全部 `asr_error`，错误 `Native ASR stream error: stream response reported failure`；Qwen3 日志只有“流式命令失败”无细节。
- 根因：`R2T2StreamSession.start()`（`src-tauri/resources/r2t2_stream.py:97`）要求 `session_id > self._last_session_id`，常驻 Python 进程内严格递增。首页录音用 `native_recording.rs::NEXT_NATIVE_SESSION` 小整数（1、2、3…）；而 `commands/audio_import.rs` 用 `next_import_stream_session_id().unsigned_abs()`（毫秒时间戳 ≈1.79e12）当原生 id，把 `_last_session_id` 抬到万亿级，之后所有录音都被判为旧会话 → Python 返回 success=false → Rust 报上面的错。
- 修复：`native_recording.rs` 新增 `pub(crate) fn next_native_session_id()`（原 static `NEXT_NATIVE_SESSION` 包装），录音与导入都从该共享计数器分配；`audio_service/mod.rs` 再导出；`audio_import.rs` 改用 `next_native_session_id()` 并加回归单测。导入的**前端事件负数 sessionId** 仍用时间戳，不受影响。
- 附带改进：`asr_stream_server.py` 捕获异常时日志带上 `exc` 文本，避免以后再只有“流式命令失败”。
- 验证：`cargo check --lib` 通过；`cargo test --lib commands::audio_import` 4 例全过；`cargo fmt --check` 通过。
- **运行状态提醒**：被污染的 Python 常驻进程要重启应用才会重置 `_last_session_id`；当前已无 python/light-whisper 进程，下次启动即恢复正常。
- 文档：`docs/neo/import-audio-transcription-plan.md` 3.2 增加“不用时间戳当原生会话 id”的约束说明。
