# 轻语 Whisper - UI 改版 PRD

> 状态：第一阶段已实施（v1.7.14），本文档已按实际交付更新。
> 原始高保真 Demo（ui-demo/index.html）已完成使命，随本版删除。

## 1. 背景与目标

### 1.1 现状
改版前采用 420×560 竖向单栏小窗布局，仅适合「录音工具」快速使用。随着功能扩展（历史记录、助手对话、设置等），空间受限，页面切换只能依赖小窗内跳转。

### 1.2 目标
改为「左侧全局导航 + 右侧内容」双栏布局，为后续功能扩展提供信息架构基础。

### 1.3 与原方案的差异
原始 PRD 提出三栏布局（Sidebar + 列表面板 + 内容区）、蓝色主题、底部输入栏。实施过程中收敛为更贴合现有功能的两栏方案：
- **保留**：左侧全局导航、窗口放大、设置页导航栏内嵌
- **推迟**：中间列表面板（笔记/文件夹分组）、底部输入栏、蓝色主题切换 —— 作为后续迭代方向，不在本期范围

- 删除设置页底部 footer（品牌/版本信息已上移至侧栏，避免重复）
- 导航点击滚动定位到对应设置分组

### 2.4 历史记录：录音文件定位
- 已保存音频的历史卡片，操作栏新增「打开录音所在文件夹」按钮（FolderOpen 图标）
- Rust 侧 `reveal_history_audio` 命令：按记录 ID 服务端解析音频路径（`safe_audio_path` 防目录穿越 + 文件存在性校验），Windows 下 `explorer /select` 选中文件，其它平台打开所在目录
- 安全约束：前端只传记录 ID，不允许指定任意路径
- 失败时 toast 透出后端错误（文件不存在或已被清理）

### 2.5 i18n 补充
新增 key：`app.navFeatures / navHome / navHistory / navSettings`、`result.liveTranscribing`（保留）、`historyPage.openAudioFolder / audioFolderUnavailable`。

## 4. 待定项（需要产品决策）

### 4.1 实时转写预览的位置
背景：听写时识别中间结果目前只显示在字幕悬浮窗。用户反馈希望去掉悬浮窗、改为在主页面结果框内实时展示。

已实现过一版（结果框覆盖式预览 + 设置开关控制浮层）后回滚，**尚未定稿**。核心矛盾是两种使用场景需求不同：

| 场景 | 主窗口状态 | 需要的反馈 |
|---|---|---|
| 在主页面点录音 | 可见 | 结果框实时预览即可，悬浮窗多余 |
| 热键在其它应用听写 | 隐藏 | 悬浮窗是唯一实时反馈，没有它只能盲说 |

候选方案：
- **A. 设置开关**：默认关闭浮层，主页面结果框实时预览；开关开启恢复悬浮窗（已实现过，代码可复用）
- **B. 按主窗口可见性自动**：主窗口可见不弹，隐藏时弹
- **C. 彻底删除悬浮窗**：最简单，但热键听写场景无反馈

决策后需一并处理的技术细节（上次实现踩过的坑）：
1. 原生流式引擎（Qwen3-ASR）首条假设到达有 1~2 秒延迟，结果框需在录音开始即渲染（空框+占位提示）
2. `recording-state` 事件需清残留 interim，避免取消录音后幽灵文本冻结
3. 迟到的旧会话 final 不能清当前会话的实时预览
4. live 期间隐藏上一条结果的统计行，避免误导
5. Rust 侧 SQLite 读取需走 `initialize().await?` + `spawn_blocking` 惯例

## 4. 技术实现

### 4.1 前端
- 保持 React 19 + TypeScript + 现有 CSS 变量主题体系（未引入 Tailwind，未改主色调）

- IPC 策略：main 窗口默认放行，无需改白名单
